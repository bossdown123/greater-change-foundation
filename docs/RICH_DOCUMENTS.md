# Authored content and shared drafts

Long-form content uses Tiptap. Stories, introductions and newsletter bodies support paragraphs, headings, lists, emphasis, safe links, alignment, and library figures. Image metadata remains plain text; Tiptap provides the editing surface without allowing markup in alternative text. Existing prose loads without transformation until edited. The renderer constructs React elements from an allowlisted tree; it never injects stored HTML.

The versioned `gcf-richtext:` representation is an authored document value in the existing text field, rather than a container for dates, amounts or other charity facts. All such facts remain in their existing normalized relations. Image references are additionally indexed and enforced through `event_inline_media`, `initiative_inline_media`, `campaign_inline_media` and `newsletter_inline_media`. These relations have only candidate-key attributes and satisfy BCNF/5NF; the newsletter key includes the independent document field. This intentional derived reference index lets the database enforce image retention and answer usage queries without parsing document text. A single audited save validates the document and replaces its reference rows atomically.

Per-use captions and alternative text are authored document content. They start from the library metadata at insertion and do not overwrite that metadata. Rich content never accepts arbitrary image URLs. The library source remains private. HTML exports preserve formatting and reference authenticated image endpoints; public email delivery is not enabled.

Migration 7 adds the reference relations and their audit guards. It leaves existing prose and images untouched. Revert removes the reference index while preserving original document strings and audit history. An application downgrade after rich content is authored requires restoring the deployment backup or using a renderer that understands the versioned format.

Choosing New immediately persists a draft with an attributed creator, an ID, an untitled name and empty optional facts. A client-generated random creation key is the record ID; retries return the same owned draft without overwriting later changes or creating duplicate audit entries. Creation is guarded atomically, and another account cannot claim an existing ID. The URL includes the draft ID, and presence attaches immediately. Subsequent editing keeps the existing manual Save and conflict checks. Leaving a draft never deletes it.
